Does the lint LSP make coding agents write cleaner Robot Framework?

Long image

A

Answer

Yes: with the LSP and its auto-fix hook, agents leave 70 to 100 percent fewer lint issues. On Haiku and Sonnet that costs about 10 percent more.

  1. Haiku left 4.7 issues per run with the LSP, against 18.5 without it and 13.2 with the robocop MCP.
  2. Sonnet left 2.0 issues against 12.0, and Opus left 0 against 11.0.
  3. Every run in every arm finished with passing tests and a clean dry run.
  4. The LSP costs less than the robocop MCP on all three models.

Applies toMeasured 2026-11-14 on one task: write two Robot Framework suites with keywords and run them. Haiku 25 runs per arm at default effort; per-model check 3 runs per arm at medium effort. Plugin version c84eb65. Lint issues = robocop 9.4.0 default findings left in the final files.

How does a finding reach the agent and get fixed?

Diagram structure
  • Agent edits file edit
  • Auto-fix hook hook
  • LSP lints buffer lsp
  • Diagnostics pushed push
  • Agent fixes rest agent
  • edit → hook · PostToolUse
  • hook → lsp · didChange
  • lsp → push · short lines
  • push → agent · next turn
  1. Agent edits file ↗

    The agent writes or edits a .robot or .resource file.

  2. Auto-fix hook ↗

    Runs robocop format ReplaceWithVAR and check --fix for safe rules; prints nothing.

  3. LSP lints buffer ↗

    Robocop defaults plus the RFL rules, warning floor, at most 20 findings.

  4. Diagnostics pushed ↗

    One line per finding, at most 120 characters, with a fix hint where one exists.

  5. Agent fixes rest ↗

    Only findings robocop cannot fix reach the agent, such as long keywords.
